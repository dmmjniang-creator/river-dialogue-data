# 约定

> **什么时候读我**：看到退出码、看到「未核」、要判断「这算不算做成」、或者接手这套东西不知道某个信号是什么意思。
>
> 2026-11-09 老大提的一句：「河流的忘有声是约定实现的，不是河流自己的。所以要把相关的约定拿出来。」

## 开头这句最要紧

**「丢要有声音」不是机制自己长出来的，是我们约定的。**

脚本只会返回一个数字。**0 和 1 本身没有含义**——是我们约定「1 代表有问题、要停下来看」。约定在，机制就有意义；约定丢了，脚本照跑，数字照出，但没人知道它在说什么。

这不是理论问题。换个我、换个人、或者隔半年回来看，看到 `process.exit(1)` 很可能以为「跑完了」。那份清单要解决的就是这个。

## 一、退出码

**看见非 0 就停下，别往下推。** 这条比下面每个具体数字都重要。

| 脚本 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| `记忆同步.mjs` | 都正常 | **日记两边对不上**，或**容量预警**（单文件近 2 MB / 一层近 2000 个） | — |
| `记忆体检.mjs` | 全绿 | 漏条 / 死链 / 数量不符 / 缺键 / 日期格式错 / 底账名不符 / 别名撞车 / 事实键重复 / **投影落后** | — |
| `库锁.mjs`（被归档和同步调用） | 抢到锁 | — | **等满了还没抢到**（对方还在跑） |
| `体检.mjs`（归档那套的旧检查） | 好 | 有异常 | — |
| `抽钩子.mjs` | 好 | 出错 | — |
| `记忆备份.ps1` | 校验通过 | **校验失败**（三个探针跟磁盘对不上） | — |
| `产出体检.mjs` | 好 | 发现问题 | — |
| `基线.mjs` | 好（没有基线也是 0，不算错） | — | — |

**退出码 2 只有一个来源：库锁。** 它的意思不是「坏了」，是「这一轮先不动，下次再来」——数据一个字节都没改。**别把它当失败去重试**，那会跟正在跑的进程打架。

**`记忆体检` 里有一处特别约定**：「底账该核一下」（底账页 30 天没更新过）**不算错，退出码还是 0**。它是提醒，不是坏。

## 二、参数

| 参数 | 约定 |
| --- | --- |
| `--dry` | **只看不改**。不落盘、不动游标、不抢锁 |
| `--prune` | 删掉映射不回源的孤儿投影 |
| `--日记同步` | 把 `diary\` 的日记**单向**补到 `记忆库\日记\`。方向永不反过来 |
| `--commit` | 同步完顺手 `git commit`（有改动才提交） |

## 三、文字标记

**这些词是我们约定的信号，不是随口一说。**

| 标记 | 意思是 | 看见的人该做什么 |
| --- | --- | --- |
| **未核** | 我没验过，只是推测 | 别当结论用；要用于判断就先验 |
| **查不到** | 核过了，没有 | 可以当「不存在」用，但不能当「没发生过」用 |
| **找不到 ≠ 没发生** | `memory_find` 零命中只说明「原文里撞不到」 | 别据此说「从没有过」 |
| **判不到（SKIP）** | 拿不到证据 | **不许写成「通过」**（这条是跟别人学的，见下） |
| **接管锁** | 上一个进程死了，我接着跑 | 不是报错，是正常恢复 |

## 四、顺序上的约定

有些东西的价值全在顺序，反了就出事：

| 顺序 | 为什么不能反 |
| --- | --- |
| **归档 → 同步** | 归档会改看板和条目；先同步的话投影马上就旧了，得再补一次 |
| **重启 → 开群** | `archiveScope: home` 是启动时读的；先开群，群话会进归档和召回 |
| **先答 → 再核库 → 才判**（记忆探针） | 翻着库答题，测的是检索不是记忆；不核库就判，会冤枉自己 |

## 五、这些约定怎么改

**跟 `结构\底线.md` 一样：老大一句话就能改**，不用查出处分。改的时候记一行谁定的、改了什么。

**唯一不能随便改的**：改退出码的含义要连脚本一起改，只改这份清单等于让清单和实现对不上——那比没有清单更坏。

## 六、丢了一条约定会怎样

举个真例子（2026-11-08）：`记忆备份.ps1` 的校验探针里写死了 `底账/不忘.md`，后来那页改名成 `记忆不忘.md`。

**结果是备份校验立刻失败**——不是因为备份坏了，是因为**探针还指着旧名字**。

这说明两件事：

1. 约定写进代码之后，**改名要连约定一起改**
2. 反过来说，**它确实响了**——这正是「丢要有声音」在起作用

所以这份清单的价值不在「知道得多」，在**知道哪个数字对应哪件事**。
