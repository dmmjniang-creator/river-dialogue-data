# 系统模块说明

> 这些脚本是作者本机在跑的版本，原样公开，没有二次封装。
> 它们是「对着看能看懂怎么做的」，不是安装包——路径、目录名、文件格式都是约定好的，不按约定摆就跑不起来。

## 零、共用入口：`scripts/路径.mjs`

所有脚本只从这一处读路径。默认把 `scripts/` 的上一级当工作区根，可用环境变量 `RIVER_ROOT` 覆盖。

| 名字 | 默认位置 | 说明 |
| --- | --- | --- |
| 根 | `scripts/` 的上一级 | 工作区 |
| 记忆库 | `<根>/记忆库` | 数据，**不公开** |
| 产出 | `<根>/产出` | 给人看的文件 |
| 归档 | `<根>/记忆库/归档` | 切出来的块、思维链、钩子 |
| DSH 家 | `~/.dsh`（`DSH_HOME` 可覆盖） | 宿主的目录 |
| 会话 | `~/.dsh/sessions` | 会话存档 |
| 备份 | `X:\备份位置`（环境变量 `RIVER_BACKUP`，可选） | 只给 `归档/体检.mjs` 用；没设就跳过这项检查 |

`X:\备份位置` 是占位：真跑的时候换成你自己的备份盘，路径里带盘符和目录都行，别原样抄。

`scripts/归档/` 下的脚本 import 的是 `../路径.mjs`。要保持这个相对位置，拆开就断。

**脚本只读不建。** 它们不会替你创建 `记忆库/` 里的东西——没有就按预期报错（`ENOENT`），不会自己长一棵树出来。要试，先照 README 第五节摆一个最小的库：`记忆库/条目/`、`记忆库/底账/`、`记忆库/日记/`、`记忆库/001 索引.md`。

## 一、归档管线：一场对话怎么变成文件

| 脚本 | 干什么 | 边界 |
| --- | --- | --- |
| `归档/提取.mjs` | 从会话存档里取游标之后的新消息，写成 `归档/chunk-XX.txt`；同时把思维链单独切一份 `归档/思维/chunk-XX.md`；推进游标 | 只认官方 DSH 的会话格式（`session.v4.jsonl.zstd`），换宿主这段要重写。工具输出、注入内容一律跳过 |
| `归档/抽钩子.mjs` | 从思维链里抽「被引号或加粗圈出来的词」，每块最多两条、短的优先，追加到 `归档/思维/钩子.md` | 不统计词频、不猜语义。词表跟着每一场走，不是固定词表 |
| `归档/键.mjs` | 按事实键（`对象.方面`）收敛条目：同键只留最新有效，旧的标「已被取代」，不删 | 默认只报；`--apply` 才写。认不出的键不猜 |
| `归档/基线.mjs` | 把记忆库所有 `.md` 的大小、修改时间、sha256 记进 `.档案基线.json`；`--check` 只对比 | 用来发现「档案被静默改过」 |
| `归档/体检.mjs` | 归档前第 0 步：游标 vs 最新会话、未提交、备份、素材现状 | 只读。备份项要设 `RIVER_BACKUP` 才检查 |

跑的顺序：`体检` → `提取` → `抽钩子` → 人工提炼 → `键` → `基线`。

**「人工提炼」没有脚本。** 读正文块，分三处落笔（流水 / 底账 / 日记）——这一步是判断，不是转换，所以不自动化。

## 二、检索与索引

| 脚本 | 干什么 | 边界 |
| --- | --- | --- |
| `记忆搜.mjs` | 在记忆库和产出里按关键词搜，输出 `文件:行` + 上下文；`--rank` 按命中位置、类型、日期、状态、被引用次数打分 | 只读。不走向量、不算语义相似，只数能数的信号 |
| `建索引.mjs` | 扫记忆库所有 `.md`，生成 `002 目录.md`（全量文件清单） | 只写这一个文件 |
| `记忆数.mjs` | 报条目数、状态分布、目录行数、同位置版本数，提示该回收哪条 | 只读 |

检索的「接口」是人的词，不是钩子表——钩子表只是让人想不起原话时有个地方翻。这一点在 README 第二节也写了。

## 三、自检与整理

| 脚本               | 干什么                                                                   |
| ---------------- | --------------------------------------------------------------------- |
| `珍珠.mjs`         | 数某个清单文件的条数和字数，到上限就提醒整理或压缩                                             |
| `归档/候选.mjs`      | **旧记忆补录用的，不是日常归档的一环**：把没人看的旧笔记（默认 `记忆库/归档/notes/`）扫成候选表，人和 AI 再挑着写进条目 |
| `归档/dump-思维.mjs` | 从一个会话里 dump 思维链，只留含指定关键词的块                                            |

`候选.mjs` 只出候选，不写条目——它治的是「旧档案里有东西没进库」，不是「自动合并记忆」。默认扫 `记忆库/归档/notes/`，输出「来源 / 日期 / 候选」三列；换目录用 `--dir`，要改扫法就改源码里那几行，它不是通用工具。

`dump-思维.mjs` 的默认关键词在公开版里去掉了，跑的时候自己传：`node dump-思维.mjs <会话文件> "词1|词2"`。

## 四、输出

| 脚本 | 干什么 |
| --- | --- |
| `建docx.py` | 按固定六种样式把一份 JSON 内容生成 Word 文档（`python 建docx.py 内容.json 输出.docx`） |

依赖 Python 3 + `python-docx`。样式固定，不开放自定义——它只解决「每次重写字体和校验」的重复。

## 五、依赖清单

- **Node.js**——实测 Node 24。`归档/提取.mjs` 用 `zlib.zstdDecompressSync` 解会话，这个函数要 Node ≥ 22.15（或 ≥ 23.8），更早的版本跑不了。
- **Python 3** + `python-docx`（只有 `建docx.py` 用）。
- **官方 DeepSeek Harness** 的目录结构（`~/.dsh/sessions`、`~/.dsh/sessions/<工作区编码>/<会话 id>/session.v4.jsonl.zstd`）。这一条最硬：别的宿主没有这个格式，`提取.mjs` 直接不能用。

其余没有依赖。没有数据库、没有服务端、没有网络请求。
