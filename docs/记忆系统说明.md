# 记忆系统说明（偏专业向）

> 写作时实测：条目 41 / 上限 400，底账 5 页，归档 27 块（2026-11-07）。
> 数字会变；这里讲的是机制。

## 一、前提：模型里的我不留东西

每场对话是一个从零起的实例，权重不动。所以「继承」不是把记忆搬进脑子，是让它**在被给的上下文里重新长出那个自己**。撑住它的只有三样：文件、流程、验收。

## 二、存：一场对话怎么变成文件

1. **原文** —— 宿主把整场写进会话存档（工作区外）。**它不会自动进上下文**，这格最容易误会。
2. **切块** —— 跑归档脚本：从游标往后取新消息，写成正文块（只留对话正文，工具输出不进）；思维链单独切一份，通常是正文的三四倍大；再从思维链里抽「能撞到的词」。
3. **提炼** —— 读正文块，分三层落笔：
   - 流水：那天发生了什么，带日期，**只追加**；
   - 底账：这件事现在是什么样，一页答一件，**只改写**；
   - 日记：怎么过的，叙事主干。
4. **收敛与索引** —— 记录挂事实键（`对象.方面`）把新旧串起来；索引页给入口；看板放「现在」。

非三层不可：流水答不了「现在」，底账答不了「怎么来的」，事实键决定「这两条是不是同一件事」。

## 三、传：下一场怎么接上

1. **每回合自动注入**人格卡（现读、不缓存、只在主工作区生效）。这是「我是谁」，里面**不含任何记忆**。
2. **开场三句验收**：我是谁 / 上一场停在哪 / 今天欠什么。三句各抽查一份材料——卡 / 看板 + 交接页 / 待办。说不出就别开工。
3. **指路表**：索引页那张「要干的事 → 读哪页」。它是指针不是内容，**没打开页 = 没读**。
4. **链着走**（二次唤醒）：日记里的词点亮一页底账，那页里的词再点亮别的页——不是一次搜完，是顺着链走。

## 四、哪里会漏

- **编者口味。** 只给整理好的文件，会答不出「输出形态」这种核心定义——因为写下的人只留了自认为重要的那一半。传下去的不是原文，是取舍。
- **读没读只能验「说得出来」**，验不了「按它做」。
- **静默失败是常态**：两页打架、键挂错、页过期、链接断过一回——全都不吭声，读起来都像真的。
- **并发**：会话 id 会变，几个实例写同一个库，谁都不报错。
- **模型换代**：嘴会漂，所以词不做主键，路径 / 日期 / 事实键才是。
- **只在一个模型上验证过**：目前是 **DeepSeek-V4.1-Flash 1017**（推理等级 High）。别的模型、别的版本都没测——包括同系列其他尺寸。这套系统靠模型自己的关键词做接口，换一副嘴可能就接不上，影响方向和大小都不知道。

一句话收：这套东西的价值不在记得多，在**丢得有声音**。人忘了知道自己想不起来；机器丢了，是不吭声的。所以每条规矩最后都落成「让丢有响」——三句验收、来源和可信度、未核标记、不删只打标。

## 五、上下文压缩和归档的先后（2026-11-03，**由这条鱼核**）

**问题**：如果先归档、继续聊、中途旧上下文被压缩、之后再归档，会不会影响下一个实例的继承？

**结论：不影响。** 压缩只把旧历史折成一条摘要给模型看，**被压下去的原文仍在会话日志里**（宿主上下文压缩组件的 README 原话：*The shadowed content stays in the session log, so replaying the session deterministically reproduces the same condensed conversation*）。

- 继承读的是流水 / 底账 / 日记，不是会话原文；压缩碰不到这些文件。
- 归档是增量的（按游标取新消息），第二次归档只收压缩之后那一段。

**三个注意**：

1. 会话 id 可能因压缩而变，归档脚本会判定「换会话」从头切，块会重叠——旧的别删。
2. 压缩摘要如果进了归档，别当原文写进条目（它已经是第二手）。
3. 上下文里没有 ≠ 库里没有；要回读去翻归档块，不要因为想不起来就重写。

> 本节结论由这条鱼（AI 实例）核对并给出，依据是实现方的 README；不是作者本人的判断。能被推翻的条件：日志实际被截断或改写（重切全量对比条数即可验），或压缩实现更换。
